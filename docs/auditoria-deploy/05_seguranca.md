# 05 · Segurança e configuração

Auditoria somente leitura, branch `logistica-melhorias`, 2026-11-19. Nenhum valor de segredo aparece aqui: só `arquivo:linha` e o tipo do dado.

## Resumo

- **Bloqueia o deploy (1 achado):** a API cria e **redefine a cada inicialização** um superusuário `admin` com senha fixa escrita no código. O repositório no GitHub é **PÚBLICO** e a API de produção está publicada na internet pelo túnel Cloudflare. Na prática, qualquer pessoa pode entrar como administrador na produção. Isso já vale hoje, porque o código está em `main` e nas tags `api-v0.9.0` em diante.
- **Corrigir antes (8 achados):** segredos da API de dev são públicos e a dev também está na internet, `/docs` e `/openapi.json` ficam abertos, não há limite por IP no login, uma rota sem autenticação grava no banco, a senha mínima é 4, há dados de clientes no repositório público, o ambiente `production` do GitHub não tem proteção e há divergências entre a documentação e o código.
- **O que está bom:** Argon2id; refresh token com rotação e detecção de reuso, guardado só como hash; DPAPI no Desktop; nenhum segredo real no histórico do git (só valores de dev e de teste); segredos de produção (`.env.production`, fora do git) com 64 caracteres e diferentes dos defaults públicos; container rodando sem root e com imagem base fixada por digest; Postgres sem porta publicada; erro 500 genérico, sem stack trace; access log sem query string nem headers; sanitizador de auditoria; HMAC do Almox+ com `compare_digest` e janela de 300 s; proteção contra path traversal em updates e anexos; TLS verify nunca desligado.
